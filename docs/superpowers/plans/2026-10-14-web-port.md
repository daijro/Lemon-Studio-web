# Lemon Studio desktop and browser implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Build the existing Lemon Studio editor for the browser while retaining the existing Windows, Linux and macOS application and plugin builds.

**Architecture:** Keep the model, FLP serialization, DSP, editor logic and rendering shared. Introduce browser implementations only at window, audio, plugin-host and file boundaries. Prove the two unsupported dependencies before integrating the application; a successful compilation does not prove runtime compatibility.

**Tech Stack:** Rust, wasm32-unknown-unknown, winit 0.30, softbuffer 0.4, tiny-skia, the locked CPAL 0.18.2 and Signalsmith Stretch 0.1.3, wasm-bindgen, browser AudioWorklet and storage APIs.

**Spec:** `docs/superpowers/specs/2026-10-14-web-port-design.md`

## Global constraints

- Preserve Windows, Linux and macOS behavior, including native VST3/CLAP/FL plugin loading, plugin windows, audio/MIDI devices, file dialogs and exports.
- Keep the default desktop dependency features and build commands working. Browser-only dependencies use `cfg(all(target_arch = "wasm32", target_os = "unknown"))`. Do not switch the whole workspace to a nightly toolchain for the web build.
- Preserve upstream branding, attribution and license notices. Work locally in this fork; publishing and Playground integration are later tasks.
- Ship the existing rack, piano roll, playlist, mixer, sampler, three-oscillator synth, parametric EQ, playback, FLP import/export, sample import and WAV export.
- Native plugin binaries are unavailable on the web. Preserve their state and sample references, and show the user what is unavailable.
- Preserve Signalsmith's algorithm. Do not substitute a resampler, silent processor or different stretch algorithm to make the build pass.
- Cancelled or malformed imports leave the active project intact. Failed saves/exports never clear the unsaved flag.
- Preserve distinct relative sample paths, including identical basenames in different folders.
- Include all runtime assets in a ZIP that works at `/fl-studio/`. Detect missing browser capabilities visibly. Do not load executable code from a CDN.
- Use `/tmp/lemon-web-target` for local build output. Pin web tooling after the dependency proof succeeds.

## Review focus

1. Desktop feature unification accidentally enables browser code or disables native plugins. Exercise native workspace builds and plugin-host tests in tasks 2 and 6.
2. A dependency compiles but panics when it starts a thread, reads a clock or touches the filesystem. Instantiate, process and destroy actual instruments in tasks 1, 2 and 4.
3. An older import or save finishes after the user has edited or opened another project. Test generation and saved-snapshot checks in task 5.
4. Missing samples and unavailable plugins disappear during a save. Assert preserved references and plugin bytes through task 5's round trip.
5. Audio initialization, storage or download failure looks like success. Inject failures in tasks 4 and 5; test startup from a nested URL in task 6.

## Evidence before implementation

Base: `39a74ac1cf5d17f6ce3e949f071e070ffed66e39`. Design commit: `2b9c913`.

- `cargo check -p os-app --target wasm32-unknown-unknown --locked` fails in NIH-plug's VST3 `OsEventLoop`/platform-view code and Signalsmith's C++ build, which cannot find `<complex>`. Log: `/tmp/lemon-web-evidence/baseline-wasm.log`.
- `cargo test -p os-model -p os-flp -p os-dsp -p os-engine --locked` exits successfully. This is a core baseline, not a desktop application or browser test. Corpus-dependent tests return early without `OPENSTUDIO_FLP_CORPUS`; one manual helper is ignored. Log: `/tmp/lemon-web-evidence/native-core.log`.
- The existing built-ins use statically linked CLAP tables, but NIH-plug's `Wrapper::new` unconditionally creates a background thread. Target-gating VST3 alone cannot fix browser startup.
- CPAL's locked AudioWorklet backend requires atomics, a rebuilt Rust standard library and cross-origin isolation. Its worklet initializes another instance of the Rust module; a separate DSP module must be available in each processing context, and its instance-local handles must never cross contexts.
- `Renderer::inline` already supports rendering without the native feeder thread. Reuse its pause/fade behavior and existing queue where practical.

## Files and responsibilities

Follow the existing layout. `crates/os-app/src/browser.rs` is the app's sample browser, so new browser-platform code belongs under `crates/os-app/src/web/`.

- Dependency boundaries: root/package `Cargo.toml` files, `Cargo.lock`, `crates/os-host`, `crates/os-clap`, `crates/os-plugkit`, and the three existing plugin crates.
- DSP proof and adapter: `crates/os-dsp/src/stretch.rs`, new `crates/os-dsp/src/stretch/web.rs`, `web/dsp/`, and `tools/web-dsp.sh`.
- Application platform: `crates/os-app/src/main.rs`, `app.rs`, `transport.rs`, `loading.rs`, `plugins.rs`, `dialog.rs`, and new `src/web/{mod,files,storage}.rs`.
- Existing plugin editor logic: each plugin's `src/editor.rs` and `src/view.rs`; add browser hosting beside native hosting, without redrawing the controls in JavaScript.
- Portable sample import: `crates/os-engine/src/sample.rs`; preserve the native file loader and cache semantics.
- Build and checks: `web/index.html`, `web/bootstrap.mjs`, `web/_headers`, `tools/web-build.sh`, `tools/web-serve.py`, `tools/web-check.mjs`, `.github/workflows/web.yml`, and the existing `.github/workflows/ci.yml`.

## Task 1: Prove Signalsmith in a browser execution context

**Files:** Modify `crates/os-dsp/Cargo.toml` and `src/stretch.rs`; create `src/stretch/web.rs`, `tests/web_stretch.rs`, `web/dsp/`, `tools/web-dsp.sh` and `tools/web-check.mjs`.

**Interfaces:** Preserve `stretch::whole(left: &[f32], right: &[f32], rate: u32, frames: usize, transpose: f64) -> (Vec<f32>, Vec<f32>)` and every public `Stream` method. The browser implementation is internal to `os-dsp`; callers must not gain JavaScript handles or a second stretching API.

- [ ] Add deterministic tests using silence, an impulse, a 440 Hz sine and stereo input at 44.1/48 kHz. Cover zero/short input, doubled duration, octave transposition, streaming reset and seek. Reuse the existing stretch tests' pitch and level bounds. Assert output length, finite samples and native/browser latency agreement; compare measured output with native fixtures using a recorded numerical tolerance rather than inventing bit equality across compilers.
- [ ] Run the tests natively, then attempt the same inputs in browser WASM. Record the expected initial failure in the C++ dependency.
- [ ] Build the exact C++ sources bundled with the locked `signalsmith-stretch` crate, preserving notices and recording checksums. Start with an Emscripten-built module exposing the existing wrapper's create/destroy, latency, reset, seek, transpose, process and exact functions. Do not substitute the latest upstream algorithm. Load it before any browser stretch object is constructed and free handles/buffers on drop.
- [ ] Prove that the chosen bridge works in the actual processing context required by the audio backend, not only the page. Check two independent instances, repeated creation/destruction, module-load failure and stale typed-array views after memory growth. Handles must stay with the module instance that created them.
- [ ] Run `tools/web-dsp.sh` and `node tools/web-check.mjs dsp`; require the fixture assertions and a real browser execution result. Record the exact Rust, Emscripten and wasm-bindgen versions that passed.
- [ ] Commit the verified dependency boundary and evidence. If this bridge cannot preserve the existing interface safely across the audio contexts, stop this task, record the concrete failure and revise the technical approach before integrating it. Do not weaken the promised audio behavior.

## Task 2: Make the built-in plugins usable without native startup

**Files:** Modify root/package manifests, `crates/os-host/src/lib.rs`, `crates/os-clap/src/lib.rs`, `crates/os-plugkit/src/{lib,linked}.rs`, the three plugin crates' `src/{lib,editor}.rs`, and `crates/os-app/src/{plugins,project_plugins}.rs`. Add browser adapter code beside the existing host code and focused plugin tests.

**Interfaces:** Keep `plugins::builtin() -> Vec<Available>`, `builtin_effects() -> Vec<Available>`, `os_host::Library`, `os_host::Plugin`, `SharedPlugin`, `SharedInstrument` and `SharedEffect`. Preserve plugin IDs, parameter IDs, state formats and native entry points. Native `Library::load` remains functional; the browser path reports that a native binary is unavailable.

- [ ] Add tests that instantiate all three built-ins, activate at 48 kHz, set a parameter, process buffers, save/reload state and destroy the instance. For the sampler, supply synthetic decoded audio. Verify note-off, oscillator output and EQ response, not just descriptor enumeration. Run native linked-plugin cases first.
- [ ] Run the same lifecycle in the browser and capture the initial native-thread/runtime failure. Audit reached calls to threads, clocks, files and native editor APIs before changing them.
- [ ] Gate VST3 exports/features and dynamic-library dependencies to native targets. Preserve the existing native linked-CLAP implementation. On the browser target, adapt the built-ins to the existing `os_host` interfaces using their existing processing, parameter and editor logic, without invoking NIH-plug's native background-thread wrapper. Any background preprocessing must finish outside the audio callback and report completion or failure.
- [ ] Exercise the plugin state and parameter paths against native-created fixtures. Unknown or unsupported states remain attached to the project. Reject a browser adapter that drops an existing parameter, changes stored IDs or silently replaces DSP.
- [ ] Run native plugin tests, `cargo check -p os-app --locked`, and `node tools/web-check.mjs plugins`. Check `cargo tree -p os-app --target wasm32-unknown-unknown -e features` for unintended native-only backends. Require actual browser instantiation and processing before accepting this task.
- [ ] Commit only after both target paths pass. Record any dependency patch with its upstream revision and purpose; do not patch the user's Cargo cache.

## Task 3: Bring up the original editor and instrument controls

**Interfaces:** Add `web::start() -> Result<(), wasm_bindgen::JsValue>` using the existing `App` and window event handlers. Keep the native `main` entry point. Browser plugin hosting must preserve the existing parameter, automation-request and editor-close behavior through `os_host::Plugin`.

- [ ] Add a browser smoke case that starts the real app, opens rack/piano roll/playlist/mixer, creates and deletes a note, and undoes the deletion. Assert the model change as well as a rendered canvas. Add resize, scale-factor, text input and pointer-release cases.
- [ ] Run it against the baseline and record the startup failure. Do not treat a placeholder page or an empty canvas as the expected editor.
- [ ] Attach winit's window to the page canvas and use its browser event loop. Keep softbuffer/tiny-skia rendering. Gate native watchdog, desktop menu/window chrome and device enumeration. Use a browser-compatible clock consistently in shared callers. Show panics and initialization failures in the page.
- [ ] Host the existing built-in editor views inside the app/page. Route their existing hit tests, drags, parameter menus, text entry and automation requests through browser events. - [ ] Run `tools/web-build.sh` and `node tools/web-check.mjs editor`. Verify the actual controls and layout visually at ordinary and high DPI; report unavailable visual inspection honestly. Run the affected native app/editor tests and `cargo check -p os-app --locked`.
- [ ] Commit the working editor milestone. This milestone alone does not satisfy the usable-audio release.

## Task 4: Connect playback and asynchronous loading

**Files:** Modify `crates/os-app/src/{transport,loading,app}.rs`, add the browser transport implementation under `src/transport/`, and extend `tools/web-check.mjs` with audio cases. Use the DSP and plugin adapters proven in tasks 1 and 2.

**Interfaces:** Preserve the existing public `Transport` methods and `State` values. Add browser-only `Transport::start_audio(&self) -> Result<(), String>` to initiate audio from a user gesture. Errors remain available through `take_error() -> Option<String>`. Each asynchronous project load carries a monotonically increasing request generation checked before applying results.

- [ ] Add start/pause/resume/stop tests, held-note release, empty-project silence, bounded output, repeated project switches and edits during playback. Assert pause does not advance the song, stopped audio becomes silent, and an old load cannot replace a newer project.
- [ ] Run native transport tests, then the browser cases before integration to establish the missing backend failure.
- [ ] Use CPAL's AudioWorklet backend if the task 1 context proof succeeds. Retain the existing native CPAL/audio-thread/feeder implementation. Reuse `Renderer::inline` where it avoids a feeder thread; do not block the main thread or perform decoding/preprocessing in the worklet callback. Resolve any failed context proof before adding another audio backend.
- [ ] Initialize/resume audio from a user gesture. Report absent isolation, unsupported AudioWorklet, rejected initialization and a suspended context. Close processing on teardown. Prepare project/sample updates asynchronously, then apply only the current generation. Release locks before browser awaits and keep callback reads nonblocking.
- [ ] Run `node tools/web-check.mjs audio` with real AudioWorklet execution and measured output. Compare deterministic sampler/synth/EQ output with native fixtures. Test denied startup, suspension/recovery and teardown. Inspect underruns while editing a small multi-instrument song; report the tested workload rather than claiming unrestricted performance.
- [ ] Commit after native transport regressions and browser audio checks pass.

## Task 5: Make imports, saves and exports safe on both targets

**Files:** Modify `crates/os-app/src/{app,dialog,loading,project_plugins,browser,presets}.rs`, reached settings callers, `crates/os-engine/src/sample.rs`, and `plugins/lemon-sampler` sample-loading callers. Create `crates/os-app/src/web/{files,storage}.rs` and focused file/persistence tests.

**Interfaces:** Add `sample::load_bytes(path: &Path, bytes: Vec<u8>) -> Result<Sample, SampleError>` and have native `load` delegate after reading. Browser file selection returns `ImportedFile { relative_path: String, bytes: Vec<u8> }`. Add `web::files::pick_files() -> Result<Option<Vec<ImportedFile>>, String>` as an async function and `download(name: &str, bytes: &[u8], mime: &str) -> Result<(), String>`. Keep project parsing/serialization independent of the picker and downloader so failures are testable.

- [ ] Test a synthetic FLP with notes, mixer settings, samples and unknown plugin state through import/edit/export/reopen. Assert plugin-state bytes and missing-sample references survive. Test `a/piano.wav` and `b/piano.wav`, malformed/truncated inputs, cancellation and a newer project superseding a pending import.
- [ ] Add save tests where serialization, storage or download initiation fails, plus an edit made while a save is pending. Assert the current project remains dirty. Run these cases before changing the existing synchronous path.
- [ ] Extract byte-level parsing and serialization from `App::open`/`save_to`; native callers keep their file-dialog and filesystem behavior. Browser callers select/read asynchronously, validate before adoption and preserve relative paths without basename fallback on ambiguous matches. Reuse Symphonia decoding, including the existing Vorbis-in-WAV handling.
- [ ] Persist preferences and local working-project/sample data in browser storage with explicit denied/quota errors. Commit project snapshots atomically, preserve the last good snapshot on failure, and restore through the same validated import path. Keep downloads usable when storage fails. A browser download cannot confirm a file was saved to disk; do not report disk persistence or clear dirty state on an unacknowledged download.
- [ ] Export WAV bytes with the existing engine and `wav::write_f32_stereo`, then download them. Preserve native WAV export behavior. Test cancellation/failure, output rate and duration, non-silent samples, and no mutation of the active project.
- [ ] Run the affected native app/sample/FLP tests and `node tools/web-check.mjs files`. Inject quota/denial/download failures; reload storage and reopen exported FLP/WAV files. Commit only after failure cases preserve user data.

## Self-review

The tasks cover the approved editor, instruments, DSP, transport, import/export, storage and distributable. The user's desktop-preservation requirement applies to each dependency/platform change and the final matrix. Existing host and engine interfaces remain the contracts; new byte-import APIs are shared by native and browser callers. Runtime audio and actual browser interaction remain required, with unavailable checks reported rather than counted as passed.

The first two tasks deliberately prove dependencies before application integration. Toolchain pins, numerical tolerances and any necessary dependency patch are outputs of those measurements, not assumptions disguised as verified compatibility. Any change to promised functionality requires an updated design; an implementation detail that passes these contracts does not need another scope discussion.
